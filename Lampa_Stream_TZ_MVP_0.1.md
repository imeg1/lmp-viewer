# Техническое задание: Lampa Stream

**Версия ТЗ:** 1.0  
**Первая версия продукта:** MVP 0.1  
**Основной язык:** TypeScript  
**Планируемый backend:** Go  
**Цель:** независимый расширяемый плагин для Lampa, который сначала воспроизводит тестовое видео, затем поддерживает реальные источники и рекламу.

## 1. Стратегия развития

| Версия | Возможности |
|---|---|
| 0.1 | Кнопка в карточке фильма, экран плагина, запуск одного тестового видео |
| 0.2 | Один реальный источник видео |
| 0.3 | Выбор качества |
| 0.4 | Сериалы, сезоны, серии, озвучки |
| 0.5 | Видеореклама после проверки совместимости и условий монетизации |
| 0.6 | Несколько источников |
| 1.0 | Настройки, диагностика, стабильность |

## 2. Выбор технологий

- **TypeScript** — исходники клиентского плагина; компиляция в обычный JavaScript.
- **Vite** — сборка в единый файл формата IIFE, без обязательных `import`/`export` во время выполнения.
- **Vitest** — модульные тесты.
- **ESLint, Prettier** — качество кода.
- **GitHub Pages** — размещение готового `plugin.js` по HTTPS.
- **GitHub Actions** — сборка, тесты, публикация.
- **Go** — будущий backend для API источников, рекламной конфигурации и аналитики; **не нужен в MVP**.

Go и Kotlin не подходят для прямого подключения в Lampa как обычного плагина: Lampa загружает JavaScript. Kotlin/JS и Go/WASM технически возможны в отдельных сценариях, но добавляют сложность. Для клиента выбран TypeScript; для будущего сервера — Go.

## 3. Область MVP 0.1

### 3.1. Инициализация

- Проверять доступность `window.Lampa`.
- Дождаться готовности приложения, используя проверенные события/механизмы Lampa.
- Регистрировать компонент плагина.
- Исключить повторную инициализацию и дублирование элементов интерфейса.
- Логировать диагностические сообщения и корректно обрабатывать ошибки.

### 3.2. Интерфейс

- В карточке фильма показывать кнопку **«▶ Смотреть онлайн»**.
- По нажатию открывать экран плагина с названием выбранного фильма.
- На экране показывать элемент **«▶ Воспроизвести тестовое видео»**.
- Поддерживать навигацию пультом: стрелки, подтверждение, «Назад».
- Возвращать пользователя в интерфейс Lampa после выхода из экрана/плеера.

### 3.3. Воспроизведение

- Использовать встроенный API `Lampa.Player.play()`.
- Запускать один общедоступный тестовый MP4 с разрешённым демонстрационным использованием.
- Не использовать отдельный HTML5-плеер или iframe.
- Показывать понятную ошибку при недоступности видео.
- **Не подменять фильм тестовым видео незаметно:** ясно обозначить демонстрационный режим.

Пример вызова (конкретную сигнатуру подтвердить по используемой версии Lampa):

```typescript
Lampa.Player.play({
  url: video.url,
  title: video.title,
});
```

### 3.4. В MVP не входят

Реклама, Go-сервер, авторизация, база данных, парсинг сайтов, прокси, автоматический поиск фильмов, сериалы, сбор пользовательской аналитики.

## 5. Контракт видеоисточников

Предусмотреть расширяемый интерфейс, но реализовать в MVP только `DemoSource`.

```typescript
interface Movie {
  id: string;
  title: string;
  originalTitle?: string;
  year?: number;
  imdbId?: string;
  kinopoiskId?: string;
}

interface VideoStream {
  url: string;
  quality?: string;
  format?: 'mp4' | 'hls' | 'dash';
}

interface VideoResult {
  id: string;
  title: string;
  streams: VideoStream[];
}

interface VideoSource {
  id: string;
  name: string;
  search(movie: Movie): Promise<VideoResult[]>;
}
```

`DemoSource` должен возвращать единственный тестовый видеоресурс. Реализовать простой реестр:

```typescript
sourceRegistry.register(new DemoSource());
```

Не реализовывать параллельный поиск по нескольким источникам до появления такой задачи.

## 6. Адаптер Lampa

Изолировать вызовы Lampa от бизнес-логики:

```typescript
interface PlayerAdapter {
  play(video: VideoStream, title: string): void;
}

class LampaPlayerAdapter implements PlayerAdapter {
  play(video: VideoStream, title: string): void {
    Lampa.Player.play({ url: video.url, title });
  }
}
```

Проверить реальные API и события Lampa по документации/исходникам. Не придумывать несуществующие методы. Зафиксировать целевые версии Lampa и ограничения совместимости.

## 7. Требования к качеству и безопасности

- TypeScript `strict: true`.
- Не использовать `any` без объяснения в адаптере внешнего API.
- Обрабатывать ошибки загрузки и воспроизведения.
- Не использовать `eval` и обфускацию.
- Не собирать IP, email и персональные данные.
- Не добавлять аналитические SDK.
- Минимизировать runtime-зависимости и размер бандла.
- Учитывать ограниченные ресурсы и устаревшие движки Smart TV.
- Исключить повторную регистрацию UI при повторной загрузке скрипта.

## 8. Тестирование

Написать тесты на:

1. Инициализацию и защиту от повторного запуска.
2. Регистрацию источника.
3. Возврат тестового видео.
4. Передачу корректных параметров в `Lampa.Player.play()`.
5. Отсутствие API Lampa.
6. Ошибки источника.

Использовать mock `window.Lampa`. Подготовить чек-лист ручной проверки на устройстве. Не считать автоматические тесты подтверждением совместимости с реальной Lampa.

## 9. Сборка и публикация

Команда:

```bash
npm run build
```

Ожидаемый артефакт:

```text
dist/plugin.js
```

Требования:

- Один самодостаточный JS-файл в формате IIFE.
- Без runtime-импортов и дополнительных JS-чанков.
- Доступность по HTTPS.
- GitHub Actions: проверка типов, тесты, сборка, публикация на GitHub Pages.
- README: установка, сборка, публикация, диагностика и ручная проверка.

## 10. Критерии приёмки

| № | Критерий | Как проверять |
|---|---|---|
| 1 | `npm install` завершается успешно | Автоматически |
| 2 | Проверка типов без ошибок | Автоматически |
| 3 | Все тесты проходят | Автоматически |
| 4 | Создаётся `dist/plugin.js` | Автоматически |
| 5 | Плагин загружается в Lampa | Вручную |
| 6 | В карточке фильма есть кнопка | Вручную |
| 7 | Открывается экран плагина | Вручную |
| 8 | Тестовое видео воспроизводится | Вручную |
| 9 | Возврат работает с пульта | Вручную |
| 10 | Повторная загрузка не дублирует UI | Вручную |

Пункты 5–10 не отмечать выполненными без тестирования в Lampa.

## 11. Планируемая архитектура после MVP

```text
Lampa → TypeScript-плагин → Go REST API
                               ├── Источники видео
                               ├── Рекламная конфигурация / VAST
                               └── Учёт событий / аналитика
```

Go-сервер появится только при реальной потребности. Интеграцию VAST предварительно проверить на целевых версиях плеера Lampa. Учитывать права на контент, условия рекламных сетей и требования к приватности.

## 12. Задание кодинг-агенту

> Реализуй MVP 0.1 плагина Lampa Stream по данному ТЗ.
>
> Используй TypeScript, Vite, Vitest, ESLint и Prettier. Собирай один IIFE-файл `dist/plugin.js`. Добавь кнопку «▶ Смотреть онлайн» в карточку фильма, экран с единственным тестовым видео и воспроизведение через встроенный `Lampa.Player.play()`.
>
> Реализуй простой интерфейс источников и `DemoSource`, адаптер Lampa, обработку ошибок и защиту от повторной инициализации. Не реализуй рекламу, backend, парсеры и дополнительные источники.
>
> Перед реализацией изучи доступные примеры API Lampa и проверь используемые события и методы. Не выдумывай API.
>
> Добавь тесты и README. После реализации запусти проверку типов, тесты и сборку; сообщи, что проверено автоматически, а что требует ручной проверки в Lampa.
>
> Избегай избыточной архитектуры и не заявляй о подтверждённом воспроизведении без тестирования на реальном устройстве.
