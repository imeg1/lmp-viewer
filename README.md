# Lampa Stream · MVP 0.1

Плагин для Lampa: кнопка «▶ Смотреть онлайн» в карточке фильма открывает
экран с одним демонстрационным видео. Воспроизведение — через `Lampa.Player.play()`.
Выбранный фильм не ищется: деморежим явно обозначен на экране и в названии видео.

Целевая среда: **Samsung Tizen, приложение Lampa v1.13.5**.
Основной сценарий проверен пользователем на Samsung QE55Q70DAUXRU с Lampa 3.3.7;
сценарии устойчивости пока проверены не полностью.

## Разработка

Нужны Node.js 22+ и доступ к npm registry.

```sh
npm ci
npm run check
```

Отдельные команды:

```sh
npm run typecheck
npm run lint
npm run format:check
npm test
npm run build
```

`npm run format` форматирует исходники. `npm run build` создаёт только
`dist/plugin.js`: один IIFE без runtime-импортов, дополнительных JS-чанков и CSS-файлов.
После сборки скрипт проверяет единственный артефакт и синтаксис ES2015.
В runtime-зависимостях пакетов нет; jQuery и API предоставляет Lampa.

Версии зависимостей зафиксированы в `package-lock.json`; локально и в CI
используется `npm ci`. При изменении зависимостей обновляйте lock-файл через
`npm install` и сохраняйте его вместе с `package.json`.

## Установка в Lampa

1. Собрать и разместить `dist/plugin.js` по HTTPS.
2. В разделе расширений Lampa добавить полный адрес файла, например
   `https://<owner>.github.io/<repository>/plugin.js`.
3. Перезапустить Lampa, открыть карточку фильма и выбрать «▶ Смотреть онлайн».
4. На экране деморежима выбрать «▶ Воспроизвести тестовое видео».

Если скрипт подключён при уже открытой карточке, открыть карточку заново.
Для удаления отключить расширение и перезапустить Lampa.

## Публикация

Workflow `.github/workflows/deploy.yml` проверяет типы, lint, форматирование,
тесты и сборку. Pull request проходит проверки без публикации.
Успешная сборка `main` публикуется в GitHub Pages; ручной запуск доступен через Actions.

В настройках репозитория **Settings → Pages → Source** выбрать **GitHub Actions**.
Плагин опубликован: `https://imeg1.github.io/lmp-viewer/plugin.js`.
Для сайта `<owner>.github.io` путь обычно `/plugin.js`, для проектного репозитория
— `/<repository>/plugin.js`. После публикации проверить прямой URL файла.
Для обхода старого кэша при обновлении можно использовать `plugin.js?v=0.1.0`.

## Структура

- `src/core` — ожидание Lampa, однократная регистрация, диагностика.
- `src/lampa` — минимальные типы внешнего API и адаптер плеера.
- `src/ui` — кнопка карточки, экран, навигация, обработка ошибок источника.
- `src/sources` — контракт, реестр и единственный `DemoSource`.
- `tests` — готовность, повторная загрузка, источник, плеер, UI и поздние ответы.

- [Чек-лист телевизора](docs/tizen-checklist.md).

При проверке прямого URL веб-инструмент получил тип содержимого `video/mp4`,
воспроизведение на Samsung QE55Q70DAUXRU подтверждено пользователем.
Предыдущий адрес Google Cloud Storage возвращал `AccessDenied` по проверке
пользователя и больше не используется.
URL находится в `src/sources/demo-source.ts`; доступность и декодирование
конкретным телевизором должны быть проверены вручную.
Предварительный fetch/HEAD не используется: он может отказать по CORS при
работоспособном прямом воспроизведении. Ошибки обрабатываются через API плеера.

## Диагностика

В консоли сообщения имеют префикс `[Lampa Stream]`. При успешном запуске
выводится версия веб-интерфейса из `Lampa.Manifest.app_version`.
`window.__lampaStream.status` имеет значение `waiting`, `ready` или `failed`.
При отсутствии API или готовности спустя 60 секунд ожидание прекращается.
После ошибки инициализации перезапустить Lampa.

При ошибке видео проверить сеть телевизора и URL демонстрационного файла,
вернуться из плеера кнопкой «Назад» и повторить запуск.
Если кнопка отсутствует, открыть карточку заново и проверить диагностические сообщения.

Реклама, реальные источники, backend, авторизация и сбор аналитики в MVP отсутствуют.
Браузерные mock-тесты подтверждают логику, а не совместимость Tizen и кодеков.
